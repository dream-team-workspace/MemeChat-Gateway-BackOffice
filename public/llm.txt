## How to read this documentation

- The live API base URL is https://gateway.dream-team.works
- Every app API path starts with /v1.
- JSON examples are illustrative. Field names are exact.
- "Current" means the live gateway as of 2026-11-07.
- "Future" means designed but not implemented in this deployment.
- No provider key, app-client key, or user token appears in this documentation.

## API surface at a glance

Public, unauthenticated:

- GET /healthz
- GET /readyz
- GET /llm.txt
- GET /llm/{file}.txt

Public, app-client authenticated:

- GET  /v1/capabilities
- POST /v1/chat/stream
- POST /v1/tts
- POST /v1/stt
- POST /v1/embeddings
- POST /v1/vectors/upsert
- POST /v1/vectors/query
- POST /v1/vectors/delete

Reserved but currently not implemented:

- GET  /v1/account
- GET  /v1/requests/{requestId}
- POST /v1/feedback
- GET  /v1/consent
- PUT  /v1/consent

Internal endpoints under /internal are not part of this public contract.

## Most important current facts

1. The app authenticates with X-App-Client-Key. The gateway, not the app,
   chooses the provider and model for each ability.
2. One app client has exactly one enabled route per ability. There is no
   automatic provider fallback chain in the current runtime.
3. Credits are not enforced yet. Public responses report zero charged credits.
   GET /v1/account is not implemented.
4. requestId is a correlation identifier. It is not yet a public idempotency
   key for chat, TTS, STT, embeddings, or vectors. Retrying a request can call
   the provider again.
5. /v1/capabilities is cached per app client and supports ETag/304. Send the
   app-client key and, when possible, If-None-Match.
6. Provider errors are returned as 502 UPSTREAM_ERROR or 503
   CAPABILITY_DISABLED. Provider response bodies are never returned.
7. /readyz checks Postgres only. Redis is an optional L2 cache and is not a
   readiness dependency.
8. The documentation files are served from the gateway at /llm.txt and
   /llm/*.txt with Content-Type text/plain.

## Canonical field naming

- JSON field names are camelCase: requestId, maxOutputTokens, inputType.
- Header names are case-insensitive; examples use canonical case.
- Ability IDs are lowercase: llm, tts, stt, embeddings, vector.
- Legacy capability IDs are accepted in chat and embeddings compatibility paths:
  chat.standard, chat.premium, embeddings.fast, embeddings.balanced,
  embeddings.quality, embeddings.code.
- Times are RFC 3339 UTC strings when present.
- IDs are opaque strings unless a field says UUID.
